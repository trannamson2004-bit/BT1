Khác biệt cốt lõi

Tiêu chíposition: relativeposition: absolute
Vị trí tham chiếuChính vị trí ban đầu của phần tử trong luồng tài liệu (normal flow)Tổ tiên gần nhất có position khác static (hoặc <html> nếu không có)

Ví dụ sử dụng trong layout responsive

Dùng relative khi cần dịch nhẹ một phần tử mà vẫn giữ chỗ (vd: hiệu ứng hover nâng card lên), hoặc — quan trọng nhất — làm khung tham chiếu cho các phần tử absolute bên trong:

.product-card { position: relative; /* làm tổ tiên định vị cho badge */ } .badge-sale { position: absolute; /* định vị trong card */ top: 12px; right: 12px; }

Dùng absolute cho các phần tử “phẳng” trên giao diện: badge giảm giá, nút đóng modal, tooltip, icon góc card. Kết hợp với % và transform: translate() để tỷ lệ theo khung chứa → responsive:

.modal-overlay { position: fixed; inset: 0; /* phủ toàn màn hình */ display: flex; align-items: center; justify-content: center; } .tooltip { position: absolute; bottom: 100%; left: 50%; transform: translateX(-50%); /* canh giữa theo % → responsive */ }

Ảnh hưởng khi deploy lên hosting & tương thích thiết bị

  • Absolute phụ thuộc vào kích thước khung chứa: Nếu dùng giá trị px cứng, trên màn hình nhỏ phần tử có thể tràn viền hay đè lên nội dung. Khắc phục: dùng đơn vị tương đối (%, vw/vh, clamp()) và media query; luôn đặt position: relative cho cha để không bị trôi về <html>.
  • Không gian trống: Phần tử absolute không đỡ chiều cao cho cha → dễ bị cắt bởi overflow: hidden hoặc footer đè lên. Khi deploy, kiểm tra trên nhiều viewport (DevTools → Toggle device toolbar).
  • Relative an toàn hơn cho layout chính: Nên dựng khung chính bằng Flexbox/Grid; absolute chỉ dùng cho các lớp trang trí phía trên. Cách này đảm bảo render nhất quán trên mọi trình duyệt khi host tĩnh (GitHub Pages/Netlify), vì không phụ thuộc JS hay server.

Câu 2 (10 điểm) — Đăng ký Domain, cấu hình Hosting & DNS

Quy trình cho website tĩnh (HTML/CSS/JS)

  1. Đăng ký domain: Chọn nhà cung cấp (VD: Viettel, Matbao, Namecheap, GoDaddy), kiểm tra tên miền trống, thanh toán, xác thực email chủ sở hữu (ICANN).
  2. Chọn hosting: Với web tĩnh JS thuần, dùng hosting tĩnh miễn phí (xem dưới). Nếu cần server-side (PHP/Node.js) thì thuê hosting chia sẻ hoặc VPS.
  3. Upload code: Đẩy code lên host (git push, giao diện kéo-thả, hoặc FTP/SFTP). Đặt index.html ở thư mục gốc.
  4. Trỏ DNS: Tại trang quản trị domain, thêm bản ghi A (trỏ tới IP server) hoặc CNAME (trỏ tới tên miền của nhà hosting tĩnh). Thêm bản ghi CNAME www để cả www và không-www đều vào được.
  5. Kích hoạt HTTPS: Cài chứng chỉ SSL (Let’s Encrypt miễn phí, hoặc nhà cung cấp tự cấp). Bật redirect HTTP → HTTPS.
  6. Chờ DNS propagation: Có thể mất từ vài phút đến 48 giờ để toàn bộ các DNS server trên thế giới cập nhật.

Vai trò của DNS

DNS (Domain Name System) là hệ thống phân giải tên miền dễ nhớ (vd: myweb.com) thành địa chỉ IP mà máy tính dùng để kết nối (vd: 185.199.108.153). Khi người dùng gõ tên miền, trình duyệt hỏi DNS server → nhận IP → gửi request tới server hosting đó. Không có DNS thì người dùng phải nhớ địa chỉ IP số.

2 công cụ deploy không cần server riêng

  • GitHub Pages: Đẩy code lên repo GitHub, bật Pages trong Settings → trang được phục vụ tại https://<user>.github.io/<repo>. Tích hợp sẵn HTTPS, tùy chỉnh domain bằng CNAME. Rất phù hợp bài tập sinh viên.
  • Netlify (hoặc Vercel): Kéo-thả thư mục chứa code hoặc kết nối GitHub repo → tự động build & deploy, cấp HTTPS, CDN toàn cầu, có thể đặt domain riêng. Hỗ trợ form & serverless functions nếu cần mở rộng.

Rủi ro bảo mật nếu cấu hình sai

  • Không HTTPS: Dữ liệu (mật khẩu, form) truyền dưới dạng văn bản rõ, dễ bị bắt gói (MITM). Trình duyệt cảnh báo “Không bảo mật”.
  • DNS trỏ nhầm / hết hạn: Trang bị chuyển hướng sang kẻ tấn công (domain hijacking) hoặc hiển thị nội dung lạ. Luôn khóa tài khoản nhà đăng ký và bật tự động gia hạn.
  • File nhạy cảm lộ ra: Upload nhầm .env, config.json chứa key bí mật lên host tĩnh → ai cũng xem được. Dùng .gitignore và kiểm tra trước khi push.
  • Thiếu CSP / MIME type sai: Dễ bị XSS. Thêm header Content-Security-Policy (Netlify cho phép qua file _headers).
  • Cho phép liệt kê thư mục: Tắt directory listing để không lộ cấu trúc file.

Ví dụ lỗi thường gặp (var trong vòng lặp + closure)

// Lỗi: cả 3 nút đều in ra 3 for (var i = 0; i < 3; i++) { document.getElementById("btn" + i) .addEventListener("click", function () { console.log(i); // i là function-scope, sau vòng lặp i = 3 }); } // Sửa: dùng let (block scope) → mỗi vòng lặp có một i riêng for (let i = 0; i < 3; i++) { document.getElementById("btn" + i) .addEventListener("click", function () { console.log(i); // in đúng 0, 1, 2 }); }

Một lỗi khác: truy cập biến trước khi khai báo với var cho undefined âm thầm, rất khó phát hiện. Với let/const sẽ ném lỗi ngay → an toàn hơn.

Debug bằng Chrome DevTools

  1. Mở DevTools (F12) → tab Sources.
  2. Đặt breakpoint tại dòng nghi ngờ (click số dòng). Chạy lại → code dừng lại.
  3. Dùng Scope panel (bên phải) để xem giá trị của biến trong Local, Closure, Global → nhận ra var bị tràn scope.
  4. Tab Console gõ trực tiếp tên biến để kiểm tra giá trị tại thời điểm dừng.
  5. Dùng debugger; trong code để dừng tại chỗ, hoặc Watch expressions để theo dõi biến.
  6. Tab Network kiểm tra file JS có tải về không (lỗi 404 hay path sai).
Khuyến nghị: Luôn dùng const mặc định, đổi sang let khi cần gán lại. Tránh var hoàn toàn trong code mới.

Câu 4 (10 điểm) — Event Delegation (ủy quyền sự kiện)

Khái niệm

Event Delegation là kỹ thuật gắn một trình xử lý sự kiện duy nhất lên phần tử cha, thay vì gắn cho từng phần tử con. Nhờ cơ chế event bubbling (sự kiện nổi bọt từ con lên cha), khi click vào một phần tử con, sự kiện sẽ nổi lên cha và ta xác định phần tử nào được click qua e.target / e.target.closest().

Ví dụ: xử lý click trên danh sách động (dynamic list)

<ul id="todoList"> <li>Học HTML <button class="del">Xóa</button></li> <li>Học CSS <button class="del">Xóa</button></li> <!-- phần tử thêm động sau này cũng hoạt động --> </ul> <script> // Chỉ gắn MỘT listener trên cha (ul) document.getElementById("todoList") .addEventListener("click", function (e) { // Kiểm tra phần tử thực sự được click có phải nút Xóa không var btn = e.target.closest(".del"); if (btn) { btn.closest("li").remove(); // xóa li chứa nút đó } }); </script>

Lợi ích khi tích hợp với HTML/CSS để tối ưu hiệu suất

  • Ít bộ nhớ hơn: 1 listener thay vì N listener → giảm bộ nhớ và thời gian khởi tạo, đặc biệt với danh sách hàng trăm nghìn phần tử.
  • Tự động hoạt động với phần tử động: Phần tử con thêm/xóa sau khi trang tải (AJAX, DOM thao tác) không cần gắn lại listener — cha đã lo hết. Tránh lỗi “click không ăn” sau khi render lại.
  • Tách biệt HTML/CSS/JS: HTML chỉ cấu trúc danh sách, CSS lo style trạng thái (vd: thêm class .done), JS chỉ nghe trên cha và thêm/xóa class. Dễ bảo trì, dễ thay đổi giao diện mà không đụng logic.
  • Tránh memory leak: Không phải gỡ listener từng phần tử khi xóa khỏi DOM → giảm rò rỉ bộ nhớ trong SPA hay danh sách cập nhật liên tục.
Lưu ý: Một số sự kiện không nổi bọt (vd: focus, blur — dùng focusin/focusout thay thế; mouseenter/mouseleave). Với các sự kiện đó cần xử lý riêng hoặc dùng phiên bản tương đương nổi bọt.
